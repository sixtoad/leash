## Intent

**Problem:** On kernel 6.18.7 the shipped native CLIs (`native-v0.3.11`, `native-v0.3.12`) cannot load `lsm_exec` (`invalid read from stack R3 off=0 size=1`), so any policy with an exec rule fails closed under `--require-lsm`. The optional `lsm_link` hard-link guard is rejected the same way (`R2 off=0`) and is silently dropped. The release gate passed because it exercises the manager image, whose BPF objects are regenerated by the Docker (bookworm clang 14) toolchain, while the CLI archives embed the host-generated (clang 18) objects.

**Approach:** Keep verifier-visible constant bounds in the path comparison/copy loops, fully initialize and check the exec path resolution (failing closed when it cannot resolve), and gate releases on a real host-kernel load of the exact objects the CLI archives embed, using a policy with open, exec and connect rules.

## Boundaries & Constraints

**Always:** Preserve exec policy semantics (prefix rules, argument deny lists, `/` permit default) and the exec audit event shape; keep `check_path_policy` `__noinline` (#63) and mutation hooks within the verifier budget (#105); stay agent-agnostic.

**Ask First:** Any Cedar or policy-format change; making a required hook optional; changing published release artifacts.

**Never:** Evaluate exec policy over bytes no resolver wrote; publish or retag a release; commit generated `*_bpf*.go`/`.o` files (they are gitignored).

|----------|--------------|---------------------------|----------------|

| Hard-link guard | `lsm_link` on 6.18.7 | Verifies (no longer silently dropped) | Optional-hook behavior unchanged |
